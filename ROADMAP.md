# Python Career Roadmap

> **Назначение:** стратегическая карта подготовки к первой коммерческой
> работе в Python. Это ориентир, а не жёсткий календарь. Переход между
> этапами определяется навыками и результатами практики, а не датой.

## 1. Главная цель

Подготовиться к первой коммерческой работе на позиции **Junior Python
Developer / Python Automation Engineer**, а также сформировать базу для
фриланса.

Долгосрочное направление --- Backend-разработка на Python и последующий
переход к Data Science / Machine Learning / AI. ML не должен отвлекать
от ближайшей цели: получить первый коммерческий опыт.

## 2. Исходная точка

По имеющейся информации на момент создания документа:

-   Python --- средний уровень по самооценке; требуется
    систематизировать знания и подтвердить их практикой.
-   Git --- базовый уровень.
-   SQL --- практически не изучался.
-   Backend --- практически не изучался.
-   Основной ближайший интерес --- автоматизация на Python.
-   Учебная нагрузка --- ориентир около 6--10 часов в неделю;
    фактическую нагрузку периодически уточняем.

## 3. Принципы обучения

1.  Небольшие блоки теории вместо больших лекций.
2.  После теории --- вопросы на понимание и практическое задание.
3.  Сначала самостоятельная попытка пользователя; подсказки и наводящие
    вопросы предпочтительнее готового решения.
4.  Проверять не только то, что код работает, но и понимание причин,
    качество и надёжность решения.
5.  Не считать тему освоенной только после прочтения объяснения: нужны
    ответы и практика.
6.  Не переходить дальше автоматически, если остались существенные
    пробелы.
7.  Дополнительные темы можно объяснять во вспомогательных чатах, не
    меняя основной последовательности обучения.

## 4. Дорожная карта

### Этап 1. Python, работа с данными и API

**Цель:** уверенно получать данные из внешних источников, понимать
HTTP/API и обрабатывать данные на Python.

Темы: - закрепление Python: функции, коллекции, comprehensions,
исключения, модули и пакеты; - основы Git и GitHub; - клиент-серверная
модель, HTTP, методы, статус-коды, заголовки; - REST API и JSON; -
`httpx` / `requests`, параметры запросов, таймауты, обработка ошибок и
ограничение частоты запросов; - обработка и валидация данных; - даты и
время: `datetime`, `date`, `time`, `timedelta`, ISO 8601, часовые
пояса; - основы асинхронности: корутины, event loop, `async` / `await`,
`asyncio`, конкурентное выполнение, таймауты и отмена задач;
- аннотации типов (`type hints`): базовые типы, типизация функций,
  `Optional`, `Union` и современные конструкции `|`;
- основы объектно-ориентированного программирования: классы, объекты,
  наследование, композиция и инкапсуляция;
- структурирование Python-проектов: разделение кода на модули
  и пакеты, организация импортов.

**Контрольная точка этапа:** - пользователь может объяснить цикл
HTTP-запроса и основные части ответа; - умеет получить JSON, проверить
статус ответа и обработать типичные ошибки; - преобразует и обрабатывает
данные без хрупких ручных манипуляций со строками; - понимает базовую
модель асинхронного выполнения и может написать небольшую
async-программу; - умеет вести изменения проекта в Git.

### Этап 2. SQL и базы данных

**Цель:** научиться хранить, извлекать и изменять данные в реляционной
базе.

Темы: - таблицы, строки, столбцы, типы данных и ограничения; - первичные
и внешние ключи, связи; - `SELECT`, `WHERE`, `ORDER BY`, `LIMIT`; -
агрегатные функции и `GROUP BY`; - `JOIN`; - `INSERT`, `UPDATE`,
`DELETE`; - подзапросы и CTE на базовом уровне; - индексы и понимание
планов запросов на вводном уровне; - транзакции и целостность данных; -
PostgreSQL; - подключение Python к БД и параметризованные запросы;
- проектирование структуры базы данных с учётом связей и ограничений
  целостности;
- анализ производительности SQL-запросов с помощью `EXPLAIN`
  на вводном практическом уровне;
- практика работы с PostgreSQL из Python, включая подключение,
  управление транзакциями и безопасное выполнение запросов.

**Контрольная точка этапа:** - пользователь самостоятельно проектирует
простую схему; - пишет запросы с фильтрацией, агрегацией и JOIN; -
подключает Python-приложение к PostgreSQL; - понимает, почему нельзя
собирать SQL-запросы конкатенацией пользовательского ввода.

### Этап 3. Backend-разработка

**Цель:** создавать и поддерживать небольшие серверные приложения.

Темы: - основы REST и проектирование API; - FastAPI; - валидация входных
и выходных данных; - CRUD; - интеграция с PostgreSQL; - конфигурация и
переменные окружения; - аутентификация и авторизация на базовом
практическом уровне; - асинхронные обработчики и работа с внешними
сервисами; - логирование и обработка ошибок; - тестирование с
`pytest`; - Docker и базовый запуск приложения в контейнере.

**Дополнительные инструменты и технологии:**

- Pydantic — модели данных, валидация и сериализация;
- SQLAlchemy — ORM, работа с моделями и запросами к базе данных;
- Alembic — управление миграциями структуры базы данных;
- Redis — основы кэширования и хранения временных данных;
- основы безопасности веб-приложений: хеширование паролей,
  безопасная работа с секретами, CORS и защита API;
- основы развёртывания Backend-приложения на удалённом сервере.

Дополнительные технологии изучаются после освоения базового
Backend на FastAPI. Глубина изучения определяется требованиями
целевых вакансий.

**Контрольная точка этапа:** - пользователь может создать API с
несколькими endpoint'ами; - приложение работает с базой данных; - есть
валидация, обработка ошибок и автоматические тесты; - проект запускается
по понятной инструкции.

### Этап 4. Автоматизация и интеграции

**Цель:** решать прикладные задачи автоматизации, пригодные для фриланса
и работы в команде.

Темы: - интеграции нескольких API и сервисов; - сбор, очистка и
преобразование данных; - парсинг сайтов там, где это разрешено и
уместно; - автоматизация файловых и офисных процессов; - планировщики и
фоновые задачи; - повторные попытки, идемпотентность и устойчивость к
сбоям; - уведомления и боты; - конфигурирование, секреты и безопасная
работа с учётными данными.

**Дополнительные инструменты:**

- `aiogram` — разработка Telegram-ботов;
- `pandas` — обработка и преобразование табличных данных;
- `openpyxl` — чтение и создание Excel-файлов;
- `Playwright` — автоматизация браузера и взаимодействие
  с веб-интерфейсами;
- основы работы с планировщиками задач и очередями фоновых задач.

Инструменты выбираются под конкретные задачи автоматизации.
Не требуется изучать все библиотеки одновременно или использовать
их в каждом проекте.

**Контрольная точка этапа:** - пользователь может самостоятельно
разобрать задачу автоматизации, спроектировать решение и довести его до
работающего инструмента; - умеет документировать запуск и ограничения; -
может оценить надёжность и обработку нештатных ситуаций.

### Этап 5. Инженерная практика и выход на рынок

**Цель:** превратить навыки в убедительное портфолио и начать системный
поиск работы и заказов.

Темы: - читаемость, структура и поддерживаемость кода; - Git: ветки,
pull request, разрешение конфликтов; - code review; - тестирование и
отладка; - README и техническая документация; - оформление 2--3
законченных проектов; - резюме и описание опыта без преувеличений; -
разбор вакансий и сопоставление требований с навыками; - подготовка к
техническим собеседованиям; - отклики, тестовые задания и первые
фриланс-заказы.

**Дополнительные инженерные навыки:**

- Linux: работа в терминале, файловая система, процессы,
  права доступа, переменные окружения и базовое администрирование
  сервера;
- CI/CD: основы автоматической проверки кода и запуска тестов
  при изменениях в GitHub;
- развёртывание приложений на VPS;
- настройка логирования и мониторинга ошибок;
- основы веб-безопасности и управления конфигурацией
  production-приложений.

**Контрольная точка этапа:** - есть несколько завершённых и
документированных проектов; - пользователь может объяснить архитектуру и
принятые решения; - готово резюме и начат регулярный процесс откликов; -
пробелы по требованиям конкретных вакансий выявляются и закрываются
адресно.

## 5. Долгосрочное направление: Data Science и Machine Learning

Переходить к нему после формирования устойчивой базы Python, работы с
данными и инженерных навыков.

Возможная последовательность: - математика и статистика для ML; - NumPy
и pandas; - анализ и визуализация данных; - scikit-learn и классические
модели; - оценка качества моделей и предотвращение утечек данных; -
основы нейронных сетей и PyTorch; - развёртывание модели через API.

## 6. Учебные проекты

### UniWork

Учебный проект для закрепления Python, HTTP API, обработки данных, дат и
времени, а затем баз данных и автоматизации.

Идея: получить расписание университета, преобразовать занятия в занятые
интервалы, вычислить подходящие свободные окна и сопоставить их с
вакансиями с совместимым графиком.

Проект --- средство обучения, а не вся программа. Не нужно искусственно
добавлять в него каждую изучаемую технологию.

### Другие проекты

Помимо UniWork необходимо разработать ещё 1–2 самостоятельных
проекта.

Каждый проект должен:

- решать понятную практическую задачу;
- демонстрировать конкретные навыки;
- иметь структурированный и читаемый код;
- содержать README с описанием и инструкцией запуска;
- иметь автоматические тесты там, где они уместны;
- храниться в GitHub с осмысленной историей изменений.

Проекты должны демонстрировать не количество использованных
библиотек, а способность самостоятельно решать инженерные задачи.

## 7. Правила изменения дорожной карты

-   Не менять глобальную цель и порядок этапов из-за случайного интереса
    к новой технологии.
-   Если рынок или требования вакансий существенно меняются,
    пересматривать приоритеты на основании актуальных данных.
-   Дополнительные темы помечать как «дополнительно», если они не входят
    в текущий обязательный этап.
-   Сроки --- предварительные оценки; качество освоения важнее
    календаря.
-   Любые существенные изменения обсуждать с пользователем и отражать в
    новой версии документа.
-   Состав технологий не является фиксированным навсегда. При пересмотре
    программы необходимо учитывать актуальные требования вакансий и реальные
    задачи коммерческой разработки.
-   Новые технологии добавлять с учётом приоритета: сначала фундаментальные
    инструменты, необходимые для целевых вакансий, затем дополнительные
    инструменты для расширения специализации.
-   Не изучать несколько альтернативных технологий одновременно без
    практической необходимости. Например, сначала освоить FastAPI, а затем
    при наличии оснований рассмотреть Django.
-   Дополнительные инструменты не должны мешать прохождению основных этапов
    и получению первой коммерческой работы.

## 8. Как использовать этот файл

`ROADMAP.md` --- стратегический документ. Он отвечает на вопрос **«куда
мы движемся и какие компетенции должны получить?»**.

Текущий статус, выполненные контрольные точки, пробелы и ближайшую
задачу записывать в `PROGRESS.md`.

Порядок подготовки и согласования изменений `PROGRESS.md` определяется
инструкциями `sysprompt.txt`. Ассистент не должен изменять файл без
предварительного явного согласия пользователя.


## 9. Подготовка к трудоустройству

Подготовка к трудоустройству начинается не только после завершения
всех этапов. Анализ рынка и требований вакансий проводится
периодически на протяжении обучения.

### 9.1. Анализ рынка

- изучать актуальные вакансии Junior Python Developer
  и Python Automation Engineer;
- выделять наиболее востребованные технологии;
- сравнивать требования работодателей с подтверждёнными
  навыками пользователя;
- выявлять повторяющиеся пробелы;
- корректировать приоритеты обучения на основании реальных
  требований рынка.

### 9.2. Подготовка к откликам

- подготовить резюме;
- оформить GitHub-портфолио;
- подготовить описание реализованных проектов;
- научиться объяснять архитектурные решения;
- подготовиться к техническим собеседованиям;
- отработать выполнение тестовых заданий.

### 9.3. Выход на рынок

Не обязательно ждать абсолютного освоения всего стека.

Когда пользователь соответствует значительной части требований
подходящих вакансий и может подтвердить навыки практическими
проектами, необходимо начинать откликаться на вакансии.

Поиск работы и фриланс-заказов ведётся параллельно
с дальнейшим обучением.

## 10. Долгосрочное развитие после первой работы

После получения первого коммерческого опыта дальнейшее обучение
определяется:

- задачами на реальной работе;
- требованиями рынка;
- выбранной специализацией;
- долгосрочными целями пользователя.

Возможные направления развития:

- углубление Backend-разработки;
- автоматизация сложных бизнес-процессов;
- Data Engineering;
- Data Science;
- Machine Learning и AI.

Переход к новому направлению должен опираться на сформированную
инженерную базу и практический опыт.
