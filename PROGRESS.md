## 1. Текущая позиция

- **Глобальная цель:** первая коммерческая работа в Python;
  развитие Backend-разработки и Python Automation как двух
  равноправных направлений; параллельное развитие фриланса.
- **Целевой уровень Backend:** самостоятельная разработка
  небольших коммерческих приложений.
- **Целевой уровень Automation:** создание надёжных инструментов
  для автоматизации бизнес-процессов.
- **Текущий этап:** Этап 1 --- Python, работа с данными и API.
- **Текущий учебный фокус:** структурирование Python-проектов
  (модули, пакеты и импорты); основы ООП уже применены в практическом
  задании, базовая практика Type Hints завершена.
  Остаются отдельные проверки надёжности HTTP-запросов.
- **Практические проекты:** UniWork и независимые упражнения
  и проекты. UniWork не является единственным источником практики.
- **Нагрузка:** ориентир 6--10 часов в неделю; уточнять при
  необходимости.

## 4. Практический проект UniWork

**Идея:** получить расписание университета из API, преобразовать его в
занятые интервалы, вычислить свободное время по дням недели и в
дальнейшем сопоставить его с вакансиями, график которых подходит
пользователю.

Известный источник данных: - API расписания Донского государственного
технического университета. - Использовавшийся endpoint:
`https://edu.donstu.ru/api/Rasp?idGroup=73007&sdate=2026-10-20` - Метод:
GET. - В JSON использовалась структура `data.rasp`. - Изучавшиеся поля:
`день_недели`, `датаНачала`, `датаОкончания`, `дисциплина`.

Уже выполнялось: - получение ответа API через `httpx`; - сохранение JSON
в файл; - извлечение списка занятий; - получение уникальных дней
недели; - преобразование времени начала и окончания через
`datetime.fromisoformat()`; - форматирование времени для вывода.

Следующие возможные задачи проекта определяются текущей учебной темой.
Не считать весь функционал проекта готовым.

## 9. Правила обновления PROGRESS.md

проверялось и какие критерии выполнены. 2. Отдельно указать темы,
которые освоены, и темы, которые только обсуждались. 3. Дать
пользователю готовый фрагмент Markdown для вставки или полный
обновлённый файл, если изменений много. 4. Указать, какие пункты
чек-листа нужно отметить, снять или оставить незакрытыми. 5. Обновить
запись в журнале изменений. 6. Не объявлять этап завершённым без
выполнения его контрольных критериев.

Между контрольными точками можно фиксировать существенные изменения, но
не нужно обновлять файл после каждого небольшого вопроса.
